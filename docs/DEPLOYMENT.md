# Deploying the live demo

Free tiers: **Vercel** (frontend), **Render** (backend), **Neon** (Postgres). Render and Vercel deploy from GitHub, so the code must be pushed first.

Free Render services sleep when idle, and the first request can take about a minute. Open the site before an interview to wake it up.

## 1. Database (Neon)
Create a project and note the host, database, user and password. Build the JDBC URL:
```
jdbc:postgresql://<host>/<database>?sslmode=require
```
Flyway creates the tables on first startup.

## 2. Razorpay (test mode)
1. Create an account and switch the dashboard to **Test Mode**.
2. Generate an API key: `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`.
3. In payment capture settings, enable **automatic capture**. Refunds need captured payments.
4. After step 3 below, add a webhook:
   - URL: `https://<render-app>.onrender.com/api/payments/webhook`
   - Events: `payment.captured`, `payment.failed`
   - Choose a secret: this is `RAZORPAY_WEBHOOK_SECRET`.

## 3. Backend (Render)
New > Blueprint, and select `backend/render.yaml`. Then set:

| Variable | Value |
|---|---|
| `DATABASE_URL` | JDBC URL from step 1 |
| `DB_USERNAME`, `DB_PASSWORD` | From Neon |
| `RAZORPAY_*` | From step 2 |
| `CORS_ALLOWED_ORIGINS` | Your Vercel URL, no trailing slash |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Your first admin account |
| `SEED_DEMO_DATA` | See below |

`JWT_SECRET` and `PICKUP_SECRET` are generated by Render. The app refuses to start under the `prod` profile without its secrets, or with the sandbox gateway.

## 4. Frontend (Vercel)
Import the repo with **Root Directory** `frontend`, and set:

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | `https://<render-app>.onrender.com` |
| `VITE_DEMO_MODE` | See below |

## Letting interviewers try it
Set `SEED_DEMO_DATA=true` and `VITE_DEMO_MODE=true` to add demo accounts, past orders, and role buttons on the login page.

The demo accounts have published passwords, including an admin. Anyone can change the demo's data, so use this only for a throwaway demo database with Razorpay in **test mode**, and never with real keys or real users.

Razorpay's test mode provides test cards and UPI ids, listed in its docs.

## After deploying, check
- [ ] `/actuator/health` on the backend says `UP`
- [ ] Refreshing `/menu` on Vercel works
- [ ] A test payment completes, and the order reaches the staff board without a refresh
- [ ] The webhook shows as delivered in Razorpay's dashboard
- [ ] Cancelling a paid order creates a refund in Razorpay's dashboard
- [ ] The camera scan works on a real phone (HTTPS is required)
